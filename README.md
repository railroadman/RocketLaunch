# FLIGHT / RocketLaunch

Интерактивная 3D-миссия на Three.js: закатный запуск Falcon 9, разделение ступеней, вывод восьми спутников на начальную орбиту и возвращение первой ступени на наземную площадку. Автоматический показ занимает **4 минуты 30 секунд**; полное расчётное время миссии — около 11,5 минуты.

## Запуск

Требуются Node.js 22.12+ и современный браузер с WebGL 2. Основная цель — ПК с отдельной видеокартой.

```powershell
npm install --legacy-peer-deps
npm run dev
```

Откройте адрес из терминала (обычно http://127.0.0.1:5173/) и нажмите **«Начать миссию»**. Звук включается после этого нажатия. На момент передачи dev-сервер запущен на порту 5173.

```powershell
npm run build
npm run preview
```

Готовая сборка находится в `dist/`. Открывать `index.html` напрямую через `file://` не следует: модульный Worker и ресурсы приложения требуют HTTP-сервера.

## Управление

| Элемент | Действие |
|---|---|
| Старт / пауза | Начать или остановить общий таймер миссии |
| Круговая стрелка | Вернуться к началу, восстановить автоматическую камеру |
| Шкала и отметки событий | Перейти к любому моменту полёта |
| Темп | Автомонтаж 4:30 или фиксированная скорость 1× / 2× / 5× / 10× / 25× |
| Режиссура | Автоматически выбирать главный аппарат и важный ракурс |
| Ступень 1 / ступень 2 | Следить за выбранным аппаратом после разделения |
| Автокамера | Переключить на свободный осмотр: вращение мышью, колесо для масштаба |
| HIGH / MEDIUM / LOW | Объёмные эффекты, bloom, тени и разрешение рендера |
| Данные и модель | Графики, таблицы двух ступеней, все события, допущения и источники |
| CSV | Скачать расчётную телеметрию обеих ступеней с шагом около секунды |
| Пробел / ← / → / R | Пауза, перемотка ±10 секунд, сброс; когда фокус вне элементов управления |

Время **T−/T+** всегда относится к миссии. Внизу отдельно указано время ускоренного показа. После разделения ступени движутся параллельно: смена камеры не замораживает другой аппарат. Перемотка восстанавливает всё состояние, включая журнал, обтекатель и спутники.

## Что реализовано

- Девять двигателей Merlin, отдельная вторая ступень, составной обтекатель, решётчатые рули и раскрывающиеся опоры.
- Стартовый стол, обслуживающая ферма с отведением конструкций, резервуары, прожекторы и наземная посадочная площадка.
- Закат, объёмные шейдеры факела и дыма с ray marching и турбулентностью, пыль, атмосферный след, переход к звёздному небу и кривизна Земли.
- EffectComposer, bloom, виньетка, блик двигателя и слабая хроматическая аберрация при разгоне. Логарифмический буфер глубины и плавающий origin поддерживают масштабы от метров до размеров Земли.
- Низкий стартовый ракурс, приближение при отсчёте, затухающая вибрация камеры и автоматические кадры разделения, возврата, посадки и отделения спутников.
- Русский интерфейс, телеметрия, графики, журнал, подробная панель модели и CSV.
- Синтезированный шум двигателей и голосовой отсчёт через Web Speech API. Русское произношение зависит от наличия русского системного голоса; установка голоса приложением не производится. Воздушный шум затихает с высотой и отсутствует в вакууме.

## Физическая модель

**Это расчётная учебная миссия, а не воспроизведение конкретного запуска и не реальная телеметрия SpaceX.** Облегчённая полезная нагрузка выбрана для демонстрации возвращения на землю.

В Web Worker интегрируется трёхмерное поступательное движение методом RK4 с шагом **0,02 с**. Модель учитывает гравитацию сферической Земли, её вращение, совместное вращение атмосферы, изменение плотности и температуры с высотой, тягу, удельный импульс, расход топлива и сопротивление. Азимут запуска выбран приближённо для наклонения 53°.

```text
q = ρ v_air² / 2
D = Cd q A
a = (T_vector − D_vector) / m − μ r / |r|³
ṁ = −T / (Isp g₀)
```

Орбита определяется по вектору положения и инерциальной скорости. Программа разгона численно подбирается по высоте, радиальной скорости и орбитальной скорости. Возврат использует прогноз места падения с сопротивлением; посадка — обратную связь по скорости и расстоянию до площадки. Ступень не переносится к центру площадки: сохраняется рассчитанная точка касания.

После отделения каждый из восьми спутников получает небольшой импульс и отдельную траекторию под действием гравитации. Масса отделившейся полезной нагрузки вычитается из массы второй ступени. Начальная орбита не является окончательной рабочей орбитой Starlink; дальнейший подъём электрическими двигателями не показывается.

Текущий результат расчёта:

| Показатель | Результат |
|---|---:|
| Начальная орбита | примерно 296,8 × 306,2 км |
| Наклонение | 52,63° |
| Разделение | T+02:15 |
| Завершение разгона второй ступени | около T+08:01 |
| Посадка | около T+08:30 |
| Ошибка посадки | около 2,49 м |
| Вертикальная скорость касания | около 0,70 м/с |
| Отделение спутников | около T+09:56 |

Численные параметры находятся в `src/sim/mission.ts`, формулы — в `src/sim/physics.ts`. Остаток топлива, скоростной напор и сопротивление выведены из этого расчёта, а не анимируются независимыми счётчиками.

### Допущения и ограничения

Ориентация задаётся программой управления; полная вращательная динамика, ветер, аэродинамическая работа рулей и CFD отсутствуют. Массы, коэффициенты сопротивления, удельный импульс и работа управления — приближённые инженерные параметры. Возврат допускает глубокое дросселирование, а посадочный импульс заметно длиннее типичного реального. Это обозначено в научной панели.

Выхлоп и дым — визуальная интерпретация, не газодинамический расчёт. Раскрытие батарей, вращение спутников, облака и камера также художественно интерпретированы. Космодром и наземная площадка условные, на прибрежной местности по мотивам Флориды. Длительный дальнейший полёт спутников, утилизация второй ступени, мобильная версия и экспорт видео не входят в эту версию.

## Проверки

```powershell
npm run check
npm test
npm run build
npm run test:e2e
npm run test:landing-earth
```

14 тестов проверяют атмосферу и сопротивление, орбитальные элементы, успешную посадку, остаток топлива, состояние ракеты при отсчёте, непрерывность разделения и моменты тяги, отдельные орбиты восьми спутников, общую длительность показа, паузу, перемотку, повтор и ручное ускорение. Регрессионные проверки подтверждают постоянство точки посадки во вращающейся системе Земли, синхронизацию координат спутников со второй ступенью, фактическую высоту события «линия Кармана» и непрерывность расширения факела.

Browser smoke использует Playwright: проверяет загрузку без ошибок JavaScript/GLSL, важные кадры, старт и паузу, смену аппарата и камеры, качество, аналитическую панель, CSV и изменение размера окна. Dev- или preview-сервер должен работать отдельно. Для проверки другого порта задайте `BASE_URL`. Скрипт использует доступный локальный Chromium из кэша Playwright; если его нет, выполните `npx playwright install chromium`.

`test:landing-earth` проверяет совпадение отрисованной точки контакта с расчётной после посадки, включая дробные моменты времени, и синий цвет океана в орбитальном кадре. Снимки: `artifacts/fix-landing.png`, `artifacts/fix-earth.png`. Земля использует локальную текстуру и отдельный шейдер нейтрального солнечного освещения с голубой атмосферной кромкой; закатное освещение космодрома сохранено.

Факел плавно расширяется по мере падения рассчитанного атмосферного давления. У сопел сохраняется узкая струя, ниже появляется широкий разреженный объём; его размеры и цвет — художественное приближение, не CFD. Камера отдаляется при наборе высоты, чтобы широкая часть оставалась в кадре. В правой панели показаны давление среды `pₐ` (отдельно от скоростного напора `q`) и состояние факела.

Пересечение 100 км происходит около **T+02:55,55**: событие «KÁRMÁN LINE / 100 KM» добавлено в журнал, таблицу и шкалу миссии. Кнопка «100 КМ» позволяет сразу перейти к нему. Автоматический показ сохраняет этот участок в темпе 1×, оставаясь длительностью 4:30. Резкого изменения факела на отметке 100 км нет. Снимки: `artifacts/03b-expanded-plume.png`, `artifacts/05b-karman-line.png`.

Снимки проверки и CSV сохраняются в `artifacts/` и исключены из Git. Проверка в программном WebGL подтверждает функциональность; целевые 60 FPS на отдельной видеокарте требуют измерения на конкретном ПК.
